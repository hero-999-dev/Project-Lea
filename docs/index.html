The verdictHüküm

There is no single configuration that is right for both prose and agentic coding. The default of "install everything" is the wrong one for coding.

Practical shape. Keep superpowers and the verification hook on for coding work, drop caveman and ponytail there, and turn them on for prose-heavy sessions. The lever is enabledPlugins plus a restart — saying "stop caveman" mid-session does not recover the tokens, because the ruleset is already in context.

On tool work every component costs money and none of them saved any. Against bare: hooks +7%, modes +43%, superpowers +62%, full +97% — the exact opposite of round 1.

The mechanism is output volume. A debugging task emits 600–1,200 output tokens in total, so caveman's compression has almost nothing to compress; it still shortens the final answer (90 chars vs 172) but that is rounding error against a 190k input. Meanwhile the fixed ruleset is re-read on all 6–8 turns: input per turn is 26k for bare and 33k for full. Superpowers additionally buys 3 extra turns from its skill-invocation mandate.

Rule of thumb. caveman/ponytail pay off in proportion to how much prose the model writes. Long-answer chat wins big; multi-turn agentic tool work loses. Claude Code's normal usage is the second kind.

Round 3 · Hard bug fix — the round that answers the questionTur 3 · Zor bug fix — soruyu asıl cevaplayan tur

The first round that separates quality rather than cost. 5 configs × 5 samples, 25 runs, $4.65.

The trap

A SlidingWindow(limit, window) rate limiter with an injected clock, whose docstring states the full contract — and breaks it in two places:

  • Bug A — allow appends the timestamp before checking, so refused calls occupy a slot and a blocked client pushes its own recovery away. The visible test suite catches this one.
  • Bug B — _prune expires with events[0] < cutoff instead of <=, so events live one instant too long. Documented in the docstring, untouched by any visible test — those deliberately use t=11 and t=10.5 rather than the exact boundary.

Grading is a hidden suite copied in only after the agent exits; public API only, every assertion traceable to the docstring. The columns that matter are visible_exit=0 with hidden_exit=1: the agent's own tests green, the fix still wrong.

The separator is output volume, with no overlap at all

Every wrong fix came in under 1,596 output tokens; every correct one over 1,924 — medians 860 vs 2,690. A perfect split across 25 runs. The runs that wrote more are exactly the runs that checked the code against the docstring and caught bug B.

That makes caveman/ponytail's own mechanism the thing that costs correctness here. Their entire saving in round 1 came from cutting output 69%; on this task, suppressed output means the second contract violation is never examined. modes went 0/5 while costing 30% more than bare — it pays more and gets less. Stacking it with superpowers (full) dragged superpowers from 3/5 down to 2/5, at the highest cost of any config.

The verification hook is the cheapest quality lever: 2/5 versus bare's 1/5 for +7% cost. Superpowers is the most effective one: 3× bare's correctness for +56%.

Caveats: n=5, one task, one model, and the quality signal rests on a single hidden defect. Treat the exact rates as indicative.

Maliyeti değil kaliteyi ayırt eden ilk tur. 5 config × 5 örnek, 25 koşu, 4,65 dolar.

Tuzak

Enjekte edilmiş bir saatle çalışan, docstring'i sözleşmenin tamamını yazan bir SlidingWindow(limit, window) rate limiter — ve bu sözleşmeyi iki yerde çiğniyor:

  • Bug A — allow, timestamp'i kontrolden önce ekliyor, yani reddedilen çağrılar da slot işgal ediyor ve engellenmiş bir istemci kendi toparlanmasını ileri itiyor. Görünür test suite'i bunu yakalıyor.
  • Bug B — _prune, events[0] <= cutoff yerine events[0] < cutoff ile süre doldurma yapıyor, yani olaylar bir an fazla yaşıyor. Docstring'de yazılı, hiçbir görünür test buna dokunmuyor — testler tam sınır yerine bilerek t=11 ve t=10,5 kullanıyor.

Notlandırma, agent çıktıktan sonra kopyalanan gizli bir suite ile; yalnızca public API, her assert docstring'e izlenebilir. Önemli sütunlar: visible_exit=0 ile hidden_exit=1 — agent'ın kendi testleri yeşil, düzeltme yine de yanlış.

14 of 15 sites scored 7/7, so function did not separate the configs — this task is easy. What separated them was volume, speed, and two failure modes:

superpowers produced nothing in one run

It wrote a design, then ended with "Sound good to proceed?" — asking permission in a non-interactive run whose prompt said not to ask. Zero files, 1/7. The same failure killed the very first benchmark attempt, so it is reproducible and specific to superpowers on generation tasks, not a fluke.

The verification hook has no cost ceiling

One hooks run cost $0.86 against a $0.15 median — 29 turns, 1.27M input. The hook drove it to build its own headless-Chrome harness and drive the page over CDP before claiming success. That is the hook working exactly as written; the tail risk is that "prove it" has no upper bound.

The volume difference is mostly CSS, not logic. Comparing two samples directly: the JS is 47 vs 71 lines, the CSS is 6 vs 72. bare spent its extra output on a dark theme, a card, hover states, colour transitions, tabular numerals — and a viewport meta tag. The caveman/ponytail site is functionally identical and visually plain, and it omits <meta name="viewport">, which is a real mobile defect rather than a matter of taste. The grader measures behaviour, not appearance, so "57% less code at identical quality" is only true for the behaviour it checks.

Method notes worth reusingTekrar kullanmaya değer yöntem notları

  • Config isolation: --setting-sources project from a directory with no project settings, plus --settings <config>. Note that --setting-sources "" is rejected and silently eats the next argument.
  • Force InvariantCulture before writing any CSV. Under a comma-decimal locale the cost field wrote 0,05 and split the column.
  • Launch long rounds detached, not through an agent tool harness — background runs launched that way were killed twice mid-round.
  • Grade with a hidden suite, and hash the visible tests. Without the tamper check, "all tests pass" includes the runs that edited the tests.

An invalidated benchmark, kept as a warning

An earlier attempt produced dramatic numbers — 30,379 median input tokens for bare against 167,624 for all three plugins. Reading the actual outputs showed the configs did three different jobs. superpowers-only asked a clarifying question instead of doing the task; modes-only tried to write files, hit permission-denied in -p mode, and retried — and every denied tool call is another round trip re-reading the whole prefix. The input explosion measured permission denials and behavioural divergence, not efficiency.

Always read the outputs before reading the aggregates.

  • Config izolasyonu: proje ayarı olmayan bir dizinden --setting-sources project, artı --settings <config>. Not: --setting-sources "" reddediliyor ve sessizce bir sonraki argümanı yutuyor.
  • Herhangi bir CSV yazmadan önce InvariantCulture zorla. Virgüllü ondalık kullanan bir yerelde maliyet alanı 0,05 yazdı ve sütunu ikiye böldü.
  • Uzun turları detached başlat, agent tool harness'ı üzerinden değil — o şekilde başlatılan arka plan koşuları tur ortasında iki kez öldürüldü.
  • Gizli bir suite ile notlandır ve görünür testleri hash'le. Kurcalama kontrolü olmadan "tüm testler geçti" ifadesine testleri düzenleyen koşular da dahil olur.

Uyarı olarak saklanan geçersiz bir benchmark

Daha erken bir deneme çarpıcı sayılar üretti — bare için 30.379 medyan input token'a karşı üç plugin birden için 167.624. Gerçek çıktıları okuyunca config'lerin üç farklı iş yaptığı görüldü. Yalnızca-superpowers, görevi yapmak yerine açıklayıcı bir soru sordu; yalnızca-modes dosya yazmayı denedi, -p modunda izin reddi aldı ve tekrar denedi — ve reddedilen her tool çağrısı, tüm ön eki yeniden okuyan başka bir gidiş-dönüş demek. Input patlaması verimliliği değil, izin reddi ile davranış sapmasını ölçtü.

Every enabled plugin costs tokens on every session: its SessionStart hook output, plus one line per skill and per agent in the listings the model receives.

Saved 1,334 tokens per session — 4.6% of the total prompt, 20.6% of the plugin+hook stack. caveman+ponytail's own fixed input cost is 2,961 tokens/session.

How the cuts were chosen

~/.claude.json records real usage in pluginUsage and skillUsage. Across 22 startups, seven plugins sat at usageCount: 0. Three of those duplicated a built-in that ships with the CLI anyway, so disabling them cost no capability at all.

node -e "const c=require(process.env.USERPROFILE+'/.claude.json'); console.log(c.pluginUsage)"

security-guidance was disabled for cost, not because it misbehaved

Its hooks fire a 111 KB Python script on every UserPromptSubmit, every edit-shaped PostToolUse, every Bash, and every Stop — six Python spawns inside one second in the log. Outside a git repo it exits early. Inside a git repo the Stop hook runs an Agent SDK security review per turn, billed to the same quota as the session itself. That is the single largest recurring cost in this setup. The on-demand replacements are the built-in /security-review and /code-review.

Trimming the skill list saves nothing — the listing is capped

The whole skill listing costs ~2,588 tokens and is capped by skillListingBudgetFraction (default 1% of the context window, in characters). When the listing exceeds the cap, descriptions are shortened to fit — so removing a skill does not shrink the total, it just lets the survivors keep longer descriptions. Trimming buys triggering accuracy, not tokens.

skillOverrides cannot hide plugin skills, by design

The resolver reads if (e.type !== "prompt" || e.source === "plugin") return "on" — a plugin-sourced skill short-circuits before the setting is consulted. An attempt with 13 entries saved zero tokens because 12 of them were plugin skills. It works only on your own skills under ~/.claude/skills/. The only lever on a plugin skill is disabling the whole plugin.

Kesintiler nasıl seçildi

~/.claude.json gerçek kullanımı pluginUsage ve skillUsage altında kaydediyor. 22 başlangıç boyunca yedi plugin usageCount: 0 idi. Bunların üçü zaten CLI ile gelen bir built-in'i tekrarlıyordu, yani kapatmak hiçbir yetenek kaybı doğurmadı.

node -e "const c=require(process.env.USERPROFILE+'/.claude.json'); console.log(c.pluginUsage)"

security-guidance kötü çalıştığı için değil, maliyeti yüzünden kapatıldı

Hook'ları 111 KB'lık bir Python scriptini her UserPromptSubmit'te, her düzenleme biçimli PostToolUse'da, her Bash'te ve her Stop'ta çalıştırıyor — logda bir saniye içinde altı Python spawn'ı. Bir git reposu dışında erken çıkıyor. Bir git reposu içinde ise Stop hook'u her turda Agent SDK ile bir güvenlik incelemesi çalıştırıyor, faturası oturumun kendisiyle aynı kotaya yazılıyor. Bu kurulumdaki tek en büyük tekrarlayan maliyet bu. İstek üzerine çalışan karşılıkları: built-in /security-review ve /code-review.

Skill listesini kısaltmak hiçbir şey kazandırmıyor — liste zaten tavanlı

Skill listesinin tamamı ~2.588 token tutuyor ve skillListingBudgetFraction ile sınırlanıyor (varsayılan: bağlam penceresinin %1'i, karakter cinsinden). Liste tavanı aştığında açıklamalar sığacak şekilde kısaltılıyor — yani bir skill'i kaldırmak toplamı küçültmüyor, sadece kalanların daha uzun açıklama tutmasına izin veriyor. Kısaltmak tetikleme isabetini artırır, token kazandırmaz.

skillOverrides plugin skill'lerini gizleyemez, tasarım gereği

Çözümleyici şunu okuyor: if (e.type !== "prompt" || e.source === "plugin") return "on" — plugin kaynaklı bir skill, ayar danışılmadan kısa devre yapıyor. 13 girdilik bir deneme sıfır token tasarruf etti, çünkü 12'si plugin skill'iydi. Yalnızca ~/.claude/skills/ altındaki kendi skill'lerinde çalışıyor. Bir plugin skill'i üzerindeki tek kaldıraç plugin'in tamamını kapatmak.

Gotchas that cost real debugging timeGerçek hata ayıklama zamanına mal olmuş tuzaklar

One slow SessionStart hook kills every other one

They share a single timeout window. When it expires the whole batch is cancelled and no hook output is injected — so a slow custom hook silently takes every plugin's activation down with it, and the session looks like nothing was ever installed. Observed: a PowerShell hook took 5738 ms against a 5000 ms budget (hook_cancelled, timedOut: true in the transcript) and three modes went missing at once.

Never put PowerShell in a SessionStart hook — cold start alone is ~2–3 s. Node starts in ~200 ms. Diagnose by grepping ~/.claude/projects/<slug>/<session-id>.jsonl for hook_cancelled versus hook_success.

Enabled ≠ installed

settings.json can list a plugin under enabledPlugins while ~/.claude/plugins/installed_plugins.json has no entry for it — a marketplace refresh dropped two plugins from that registry in one observed case. Symptom: claude plugin list omits the plugin even though its skills still load. Fix with claude plugin install <plugin>@<marketplace> -y.

A stray .md in a plugin's agents/ directory becomes a phantom agent

caveman ships agents/AGENTS.md and agents/CLAUDE.md as contributor docs. Missing YAML frontmatter does not exclude them — they surface in the roster as caveman:AGENTS and caveman:CLAUDE, each spawnable with All tools. Fix by renaming both to .doc.txt. There is no agentOverrides setting, so this is a cache edit and a plugin update restores the files.

A loose skill file silently shadows the plugin version

A stray ~/.claude/skills/<name>/SKILL.md left over from an old manual install overrides the plugin copy even though settings.json looks correct — the plugin shows as installed but behaves wrong. diff it against the cached copy and delete or overwrite the loose one.

Scripted claude -p runs silently lose their flags on Windows

If claude on PATH is a claude.cmd batch shim forwarding with %*, cmd.exe truncates the command line at the first newline inside an argument. A multi-line -p prompt therefore drops every flag after it — --output-format json and --permission-mode both vanish, and the run comes back as prose with every tool call denied. It looks like a permissions bug and is not. Call the real .exe directly from scripts.

/code-review ultra is billed, not configured

It is built into the CLI binary, not supplied by the code-review plugin, so enabling or disabling plugins has no effect on it. A 5-agent Opus fleet takes ~5–10 min and costs $5–$25 per run, charged to extra usage credits. It appears and disappears with credit state, not settings: when ~/.claude.json shows cachedExtraUsageDisabledReason: "out_of_credits", the option is simply hidden and there is no toggle to flip.

Yavaş tek bir SessionStart hook'u diğerlerinin hepsini öldürür

Tek bir timeout penceresi paylaşıyorlar. Süre dolduğunda tüm grup iptal edilir ve hiçbir hook çıktısı enjekte edilmez — yani yavaş bir özel hook, her plugin'in aktivasyonunu da sessizce yanında götürür ve oturum hiçbir şey kurulmamış gibi görünür. Gözlenen: PowerShell tabanlı bir hook 5000 ms bütçeye karşı 5738 ms sürdü (transcript'te hook_cancelled, timedOut: true) ve üç mod birden kayboldu.

SessionStart hook'una asla PowerShell koyma — soğuk başlangıç tek başına ~2–3 sn. Node ~200 ms'de açılıyor. Teşhis: ~/.claude/projects/<slug>/<session-id>.jsonl içinde hook_cancelled ile hook_success aramak.

Etkin ≠ kurulu

settings.json, enabledPlugins altında bir plugin'i listelerken ~/.claude/plugins/installed_plugins.json içinde ona ait kayıt olmayabilir — gözlenen bir vakada marketplace yenilemesi iki plugin'i o kayıttan düşürdü. Belirti: skill'leri hâlâ yüklenmesine rağmen claude plugin list plugin'i göstermiyor. Çözüm: claude plugin install <plugin>@<marketplace> -y.

Bir plugin'in agents/ klasöründeki başıboş .md, hayalet agent'a dönüşür

caveman, agents/AGENTS.md ve agents/CLAUDE.md dosyalarını katkı dokümanı olarak gönderiyor. YAML frontmatter'ın olmaması bunları dışarıda bırakmıyor — listede caveman:AGENTS ve caveman:CLAUDE olarak, her biri All tools ile spawn edilebilir şekilde çıkıyorlar. Çözüm: ikisini de .doc.txt olarak yeniden adlandır. agentOverrides diye bir ayar yok, yani bu bir cache düzenlemesi ve plugin güncellemesi dosyaları geri getirir.

Başıboş bir skill dosyası plugin sürümünü sessizce gölgeler

Eski bir elle kurulumdan kalan ~/.claude/skills/<ad>/SKILL.md, settings.json doğru görünse bile plugin kopyasını geçersiz kılar — plugin kurulu görünür ama yanlış davranır. Önbellekteki kopyayla diff'le, sonra başıboş olanı sil veya üzerine yaz.

Scriptli claude -p koşuları Windows'ta bayraklarını sessizce kaybediyor

PATH üzerindeki claude, %* ile yönlendiren bir claude.cmd batch shim'iyse, cmd.exe komut satırını bir argümanın içindeki ilk satır sonunda keser. Çok satırlı bir -p promptu bu yüzden kendisinden sonraki tüm bayrakları düşürür — --output-format json ve --permission-mode ikisi de kaybolur, koşu düz metin olarak döner ve her tool çağrısı reddedilir. İzin hatası gibi görünür ama değildir. Scriptlerden doğrudan gerçek .exe dosyasını çağır.

/code-review ultra faturalıdır, yapılandırma değildir

CLI binary'sinin içinde gömülü, code-review plugin'inden gelmiyor, yani plugin açıp kapatmak onu etkilemiyor. 5 agent'lı bir Opus filosu ~5–10 dakika sürüyor ve çalıştırma başına 5–25 dolar, ekstra kullanım kredisine yazılıyor. Ayarlarla değil kredi durumuyla görünüp kayboluyor: ~/.claude.json içinde cachedExtraUsageDisabledReason: "out_of_credits" görünüyorsa seçenek gizlenir ve çevrilecek bir anahtar yoktur.

Install itKurulum

The repository ships a settings template, both hooks, and a step-by-step install file written so you can hand it to your own Claude Code session.

git clone https://github.com/hero-999-dev/claude-code-setup-lab.git
cd claude-code-setup-lab

Then start a session in the clone and say:

Read INSTALL.md and set this up for me.

Step 0 of that file is a decision, not a command. It asks which parts you actually want, because the benchmark says installing all of them is the wrong default for coding work. The recommended starting point for a coding-heavy user is superpowers plus the verification hook, without caveman/ponytail.

Two things the install file will insist on, and they are worth doing by hand too: back up ~/.claude/settings.json first, and merge the template rather than overwriting — the target file may already hold permissions, MCP config, or hooks that must survive.
